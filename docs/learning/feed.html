Read API & "The Desk" feed

System map

The indexer stored ideas; this layer serves them. A read-only Hono API (src/api/) over the same Postgres, and a Svelte 5 SPA (web/) that renders the feed. Entry price is read from the stored baseline in route_pricing; current price is fetched live from the selected venue on each API read.

Endpoints

RouteReturns
GET /api/ideas?tab=&limit=&cursor=Feed cards, newest first. tab ∈ all/perps/stocks/tokens/markets (→ routes.instrument). Cursor = ISO postedAt. Only status='routed'.
GET /api/ideas/:idFull detail: adds thesis, context, reasoning, pipeline (steps), alternatives, quotes, subjects, plus instrument-aware trade params — target/invalidation (author's stated levels) for price instruments, and resolution (settle date + criteria, fetched live) for predictions.
GET /api/authors/:handleTrack record: ideas, routed, scored (how many have a price move), winners, winRate, avgSincePosted — all on the direction-adjusted return, so a winning short counts. The first thing no single tweet can say. Surfaced on the detail page as a single win-rate figure (see below).
GET /api/statusLast fetch time + routed-idea count, for the "live · Nm ago" header.

The card contract

One feed card (toFeedCard in serialize.ts) joins four tables — trade_ideas ⟕ routes ⟕ route_pricing ⟕ raw_posts — then fetches the selected route's current price live before rendering. Live price calls are bounded per card; if a venue is slow or rate-limited, the card carries currentPriceError instead of blocking the feed or reading a stale DB current price.

{ venueLabel:"HYPERLIQUID", direction:"long", ticker:"SOL-USD",
  sincePostedPct:-0.16, currentPrice:77.27, entryPrice:77.40,
  logoUrl:"…elbstream…/crypto/SOL",
  author:{ name:"Ansem", handle:"blknoiz06", avatarUrl:"…unavatar/x/blknoiz06" },
  text:"SOL/ETH ratio just reclaimed…", conviction:"high", horizon:"for weeks" }

Field derivations worth noting: ticker gets a -USD suffix for perps and strips the builder-dex namespace (xyz:INTC → INTC); Hyperliquid xyz:* stock perps stay in the Stocks tab; logoUrl is a string-built elbstream URL (crypto/ vs symbol/ by asset class); avatars use unavatar.io/x/{handle} with an initials fallback on error.

Instrument-aware, on the card too: the compact card mirrors the detail view's two instrument fixes so the two never disagree. A prediction's price is implied odds, so the card shows 62% / at call 62% (shared fmtOdds), not $0.62; and sincePostedPct is direction-adjusted, so a winning short reads green. Both live in serialize.ts / format.ts, shared by card and detail.

Card detail view

Clicking a card opens #/i/<id> (a minimal hash router in App.svelte — shareable, back-button works, no router dependency). IdeaDetail.svelte fetches /api/ideas/:id and renders what the compact card hides.

Two different "why"s — don't confuse them. The case (reasoning) is the author's investment argument — setup → edge → payoff — the logic a trader reads to decide whether to take the position. That's the headline reasoning section. The routing pipeline (pipeline) is how the system got from tweet to instrument (candidate → venue-validated → picked); it's audit plumbing, demoted to a collapsed "How this was routed (audit)" block, not trader-facing.

Also on the page: the full thesis, the context explainer, alternatives considered (roads not taken), the source tweet, reference pills (see below), and provenance chips (subjects, conviction, horizon, asset class, model). Alternatives are rendered trader-side, not raw — SMH 20x long, not SMH short hyperliquid maxLeverage 20 (dex: xyz) (leverage parsed from the note, venue shown only when it isn't the default Hyperliquid perp). Unrouted ideas show their reason instead of a venue. Current price is fetched live when the API serializes a card (3s timeout → currentPriceError if a venue is slow), so the feed reflects the latest mark, not the last sweep.

Trade timeframe. The author's intended holding period is captured in horizon (trade_ideas) — free text, verbatim-ish ("for the next few weeks", "intraday", "Wednesday or Thursday … on Friday"), populated on ~53% of ideas, shown as a chip on card and detail. We deliberately don't normalize it into intraday/swing/position buckets or invent an exit date for price trades — same restraint as target/invalidation. Predictions get a hard timeframe instead: the resolution endDate.
References — the web-search sources behind the enrichment. The extractor has OpenAI web search available to resolve subjects, fresh context, and tickers. Those searches emit citations (generateText's sources), which we now capture, dedupe by URL, and store on the idea (trade_ideas.references). The detail page renders them as clickable source pills (host ↗) in the provenance footer — styled in blue to set them apart from the grey metadata chips (subjects, conviction, asset class, model). They sit with the provenance because that's what they are: sources the extractor consulted to enrich context, not evidence of the author's view — per the web-search boundary, search never establishes that a post is a trade idea or its direction (those come from the author's words alone). Most posts need no search and carry no reference pills; you'll see them mainly where a ticker/company had to be resolved.
Every idea carries a complete Strategy — with provenance tags. The Strategy block gives all four legs on every idea: take profit, stop loss, hold (how long), and exit (the overall plan). The tension: authors rarely state all four, and the house rule is never put words in the author's mouth. The resolution is per-leg provenance — a leg the author stated is tagged from the author (green, stays close to their words, fed by target/invalidation/horizon); a leg they left open is filled with a disciplined, conservative suggestion tagged suggested (grey). A fabricated stop can never masquerade as the author's plan. Stored as trade_ideas.strategy jsonb; generated by the extractor for new ideas and by scripts/backfill-strategy.ts for the existing corpus (a cheap per-idea call over stored fields — no re-extraction). The raw target/invalidation columns remain as the author-only audit record.
Instrument-aware trade params — the "what's the precise trade, and where am I wrong?" question. The page flexes its numbers by instrument. For predictions the metrics header stops lying: a Polymarket price of 0.62 is 62% implied odds, not "$0.62", so it renders as IMPLIED ODDS / ODDS AT CALL / SINCE POSTED, and a Resolution block shows the settle date with the exact resolution criteria tucked into a click-to-expand <details> dropdown (the criteria are a dense legal wall — kept one click away, fetched live from Gamma via pm.marketInfo, with the stored endDate as a fallback). Same skeleton, different trade-params slot.
Author track record → a single win rate. When a trader clicks a card, the second question (after "did I miss it?") is "who's telling me this, and are they any good?" — which a single tweet cannot answer. The detail view fetches /api/authors/:handle (a second, non-blocking request — its failure or slow live-price recompute never blanks the idea) and renders, under the author's name, a win rate: e.g. @TheLongInvest — 35% win rate on 17 scored calls. It replaced a busier "N tracked · W/S up · avg ±X%" strip — one honest number beats three.

The catch it fixed: the since-posted move used to be the raw price change, which grades every short backwards (a short that fell — a win — scored negative). Now sincePostedPct is direction-adjusted (× −1 for short/no), so "since posted", the win count, and the win rate all mean "was the call right". Before the fix @TheLongInvest showed a suspicious avg +0.0% (winning longs and winning shorts cancelling); after, −1.21% avg, 35% win rate. The strip sits with the source tweet, so evidence and credibility read together.

Honest caveat: it's a mark-to-now win rate (currently in profit vs. the post-time price), not a realized win/loss at a target or stop — those aren't tracked yet (position lifecycle is parked).
No separate "Evidence" section. The verbatim quotes[] (the exact author words each idea was extracted from) used to render as a standalone "Evidence" list — but on a single tweet those quotes are just fragments of the source tweet shown right below, so it duplicated. Dropped. The full source tweet is the evidence on the page; the mechanical substring check (extractor drops any idea whose quotes aren't in the post) remains the grounding. (An interim in-place <mark> highlight of the quote spans was tried and removed — it didn't add anything the raw tweet doesn't already show.)

Two honest substitutions

The mockup shows "+3.1% today" and "4 you follow traded this". We have data for neither, so rather than fabricate: the 24h "today" number is replaced by an entry-price reference (stored entry baseline + live current price = since-posted move), and the social "you follow" footer is replaced by real conviction + horizon chips (we have no follow graph and one author per idea). Both are honestly-sourced fields, not invented numbers.

Robustness note

Structured LLM calls occasionally return off-schema (No object generated). Both the extract and route calls are now wrapped in withRetry (3 attempts) — the ETH-short demo failed once, then succeeded on reprocess.
